# P7.1 — Production Docker Compose

## Purpose

`compose.production.yml` runs AGENT.ONE in production with PostgreSQL, healthchecks,
persistent volumes, and loopback-only port binding ready for Nginx reverse proxy (P7.2).

## Quick Start

```bash
# 1. Create environment file from example
cp .env.production.example .env.production

# 2. Edit .env.production with real values
#    - POSTGRES_PASSWORD  (openssl rand -hex 16)
#    - JWT_SECRET         (openssl rand -hex 32)
#    - GROQ_API_KEY       (your API key)

# 3. Validate config
docker compose --env-file .env.production -f compose.production.yml config

# 4. Build and start
docker compose --env-file .env.production -f compose.production.yml up -d --build

# 5. Check status
docker compose --env-file .env.production -f compose.production.yml ps

# 6. Verify health
curl -s http://127.0.0.1:8080/api/live
curl -s http://127.0.0.1:8080/api/health
```

## Required Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `POSTGRES_DB` | Yes | Database name |
| `POSTGRES_USER` | Yes | Database user |
| `POSTGRES_PASSWORD` | Yes | Database password |
| `JWT_SECRET` | Yes | JWT signing secret (min 32 chars) |
| `APP_BIND_PORT` | No | Host port (default: 8080) |
| `GROQ_API_KEY` | No | AI provider API key |
| `APP_PUBLIC_URL` | No | Public base URL |
| `CORS_ORIGINS` | No | Allowed CORS origins |

## Managing Production

```bash
# View logs
docker compose --env-file .env.production -f compose.production.yml logs -f

# Stop without deleting data
docker compose --env-file .env.production -f compose.production.yml down

# WARNING: This deletes ALL production data
docker compose --env-file .env.production -f compose.production.yml down -v

# Update to a new image
docker compose --env-file .env.production -f compose.production.yml pull
docker compose --env-file .env.production -f compose.production.yml up -d
```

## Production Volume

Named volume: `agentone_production_pgdata`

- Survives container recreate and `docker compose down`
- Only destroyed by `docker compose down -v`
- Keep regular backups independent of Docker

## Bind Address

The app port is published **only on 127.0.0.1**:

```
127.0.0.1:${APP_BIND_PORT:-8080}:8080
```

This is intentional. The app is not directly exposed to the internet.
Nginx reverse proxy (P7.2) will listen on 0.0.0.0:80/443 and proxy to 127.0.0.1:8080.

## Architecture

```
┌─────────────────────────────────┐
│  Docker host                    │
│                                 │
│  ┌──────────┐   ┌───────────┐  │
│  │   app    │──▶│    db     │  │
│  │   :8080  │   │  :5432    │  │
│  └────┬─────┘   └───────────┘  │
│       │        backend network  │
│  127.0.0.1:8080                 │
└─────────────────────────────────┘
        ▲
        │ (P7.2: Nginx on :80/:443)
```

## Warnings

- **NEVER** run `docker compose down -v` in production
- **NEVER** run `docker system prune --volumes` without checking volume names
- **NEVER** commit `.env.production` to Git
- **ALWAYS** set `chmod 600 .env.production` on VPS
- Do not expose database port to host in production

## Troubleshooting

### App unhealthy
```bash
docker compose logs app
# Common: DB connection refused → wait for db healthy
# Common: JWT_SECRET too short → min 32 chars
```

### DB unhealthy
```bash
docker compose logs db
# Common: port 5432 already in use by another PostgreSQL
```

### Port conflict
```bash
# Check what's using the port
ss -tlnp | grep 8080
# Change APP_BIND_PORT in .env.production
```
